# Main Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the placeholder home page with an intro block and a professional experience list, and extract the inline avatar animation into typed modules.

**Architecture:** Astro static site on the `@sikorsky/site` theme. All styling comes from primitives already in the theme's `global.css` (`#professional-experience`, `.list-with-secondary-items`, `.caption`, `.link`) — this plan adds no new CSS beyond two spacing rules. The ~340-line inline `<script>` in `index.astro` moves into two focused modules under `src/scripts/`, gaining type annotations so `astro check` passes.

**Tech Stack:** Astro 4.16, TypeScript (strict), Playwright, `@sikorsky/site` 0.5.0

## Global Constraints

- Company names as spelled in the spec: `Bit-Service / advertise.ru`,
  `Bryansk-Soft`, `Sibedge`, `AIM`, `Tinkoff`, `Monite`, `CoachHub`.

### Task 2: Extract the inline script into typed modules

A pure move plus type annotations. **No logic changes.** Success is measured two
ways: the smoke test still passes, and `npm run build` drops from 90 errors to 0.

**Files:**
- Create: `src/scripts/home-avatar.ts`
- Create: `src/scripts/link-captions.ts`
- Modify: `src/pages/index.astro` (replace the entire `<script>` block, lines ~21–380)

**Interfaces:**
- Consumes: `mockImages` from Task 1.
- Produces:
  - `initHomeAvatar(): void` — wires the avatar→nav-logo scroll animation.
    Self-guards: returns immediately if not on `/` or if any required element is
    absent. Safe to call on any page.
  - `initLinkCaptions(): void` — wires click/Enter delegation for

- [ ] **Step 1: Create the link-caption module**

The delegation block at the very bottom of the current inline script (the
`const wrappers = document.querySelectorAll(".link-caption-wrapper")` section) is
generic, not home-specific. It gets its own module so future pages can use it
without importing the avatar animation.

Create `src/scripts/link-captions.ts`:

```ts
/**
 * Makes a `.link-caption-wrapper` clickable as a whole, so a click anywhere in
 * the wrapper (including on the caption) activates the link it contains.
 * Respects modifier-clicks and `target="_blank"`, and skips `.disabled-link`.
 */
export function initLinkCaptions(): void {
  const wrappers = document.querySelectorAll<HTMLElement>(".link-caption-wrapper");

  wrappers.forEach((wrapper) => {
    const link = wrapper.querySelector("a");
    const caption = wrapper.querySelector(".caption");

    wrapper.addEventListener("click", (e: MouseEvent) => {
      e.preventDefault();

      if (link && !link.classList.contains("disabled-link")) {
        if (e.metaKey || e.ctrlKey) {
          window.open(link.href, "_blank");
        } else if (link.target === "_blank") {
          window.open(link.href, "_blank");
        } else {
          window.location.href = link.href;
        }
      }
    });

    caption?.addEventListener("keydown", (event) => {
      if (
        (event as KeyboardEvent).key === "Enter" &&
        link &&
        !link.classList.contains("disabled-link")
      ) {
        event.preventDefault();
        link.click();
      }
    });
  });
}
```

Note the `(event as KeyboardEvent)` cast — it replaces the `// @ts-ignore` that
was in the original, and is the reason one of the 90 errors disappears.

- [ ] **Step 2: Create the avatar animation module**

Create `src/scripts/home-avatar.ts`.

**Move the existing animation code verbatim** from the `if (isHome) { ... }` block
of `src/pages/index.astro`. Do not retype it from memory and do not restructure
it. The only edits are the ones listed below.

The module's shape:

```ts
interface Rect {
  top: number;
  left: number;
  width: number;
  height: number;
  right: number;
  bottom: number;
}

/**
 * Animates the home page avatar into the nav logo as the user scrolls.
 * No-ops on any page other than "/", or if the required elements are missing.
 */
export function initHomeAvatar(): void {
  if (window.location.pathname !== "/") return;

  const avatar = document.getElementById("avatar");
  const title = document.getElementById("title");
  const logoImg = document.querySelector<HTMLImageElement>("#logo img");

  if (!avatar || !title || !logoImg) {
    console.warn("[home] Missing required elements:", {
      avatar: !!avatar,
      title: !!title,
      logoImg: !!logoImg
    });
    return;
  }

  // ---- everything below is the existing body, moved verbatim ----
}
```

The **early return** is what fixes all 70 `ts(18047)` errors: because `avatar`,
`title`, and `logoImg` are `const`, TypeScript's narrowing after the guard
persists into the nested `update()` / `onScroll()` closures. The original code
used an `else` block, and narrowing does not reach closures that way.

Four helpers need parameter and return types added. These are the **only**
signature edits:

```ts
const clamp = (v: number, min: number, max: number): number =>
  Math.max(min, Math.min(max, v));
const lerp = (a: number, b: number, t: number): number => a + (b - a) * t;
// Slight ease for a smoother feel
const ease = (t: number): number => t * (2 - t); // easeOutQuad
const getDocTop = (el: HTMLElement): number =>
  el.getBoundingClientRect().top + window.scrollY;
```

Two mutable locals need explicit types (these are the `ts(7005)`/`ts(7034)` errors):

```ts
let placeholder: HTMLDivElement | null = null;
let baseSourceRect: Rect | null = null;
```

And the one helper that builds the placeholder:

```ts
function makePlaceholderFrom(el: HTMLElement): HTMLDivElement {
```

Inside `update()`, the existing line `const sourceRect = baseSourceRect;` is
followed by property reads. Because `captureBaseSourceRect()` is called
immediately before it on the `if (!baseSourceRect)` path, TypeScript cannot see
that it is non-null. Add a non-null assertion at **both** of the two places this
pattern appears:

```ts
const sourceRect = baseSourceRect!;
```

This is the `ts(2769)` fix. Do not restructure the logic to avoid the assertion —
the call ordering is deliberate.

Everything else — `computeProgress`, `update`, `cleanupFixedPositioning`,
`scheduleCleanupAfterFade`, `onScroll`, `onResize`, `onVisibilityChange`, the
initial paint sequence, the listener registration and the `pagehide` cleanup —
moves across **unchanged**.
